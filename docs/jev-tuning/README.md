# Jev tuning: 独立ラベル付き会話データ

この文書は作成元 `codex/jev-tuning-data` のデータ担当成果物を説明します。統合後のJev実測・採用設定・限界は [results.md](results.md)、作業経過は [progress-implementation.md](progress-implementation.md) を参照してください。

このブランチはデータ・評価基準・監査のみを担当する。**Jevを実行しておらず、80%達成を示す結果はない。** Gateway呼び出し、アプリ変更、ステージング統合は行っていない。

## 使うファイル

統合担当は `data/final/` を入口にする。

| ファイル | 用途 |
|---|---|
| `data/final/real-train.jsonl` | 実録Train 60件、スコア・意味ラベル・不確実性付き |
| `data/final/real-validation.jsonl` | 実録Validation 20件。プロンプト・閾値選択用 |
| `data/final/real-test.jsonl` | 実録Test 20件。選択終了後の一度の評価用 |
| `data/final/synthetic-train.jsonl` | 日本語合成Train 36件。Testとして報告しない |
| `data/final/blind-real-*.jsonl` | 現行100件に対応する、正解を含まない入力 |
| `data/labels-final.jsonl` | 現行実録100＋合成36件の注釈。`reviewed`と不一致フラグを保持 |
| `data/review-independent.jsonl` / `data/review-boundary.jsonl` | 他ラベル・Jev予測を隠した再判定 |
| `data/adjudication.jsonl` | 初回／再判定の比較と暫定採用方針 |
| `rubric.md` | 各パラメータ32項目と反例、スコアアンカー、判定手順 |
| `audit-report.json` | 件数・出典一致・漏洩・分布・ファイルハッシュ。モデル精度ではない |
| `sources/README.md` | 論文、権利者、版、ライセンス、改変のクレジット |

`data/blind-train.jsonl`, `blind-heldout.jsonl`, `labels-train.jsonl`, `labels-heldout.jsonl` は**最初のサンプリング100件の歴史記録**。差し替え前の10件を含むため、そのまま現行評価に使わない。初回ラベルを消さず、`package_data.py` が現行IDだけを採用する。`sources/word-checks-baseline.jsonl` も初回用。最終100件の照合は `word-checks-final.jsonl`。

## データの性質と限界

- 実録100件は、英語で実際に行われた**設定付きリモコン設計会議**の抜粋。日本語の自然な業務会議ではない。AMI / AMI-ME、CC BY 4.0。
- 20会議系列を先にTrain 12系列、Validation 4系列、Test 4系列に分離し、各系列5件。末尾a–dが異なっても同系列は同splitに置いた。100件は100独立会議を意味しない。異なる系列間の話者共有まで排除した分割ではない。
- 初回は各系列でhash選択した1会議から5区間を選択。その末尾判断がすべてOKだったため、同じ分割内で10件を困難事例候補に置き換えた。**90件の広い抽出＋10件の目的抽出**であり、ランダム代表標本とは呼ばない。最終状態では一部系列に複数の会議a–dが含まれる。
- 同一segmentの短窓／長窓が2組（同split）あり、独立した元segmentは98件。同一議論でも観測末尾が違う。Jevの状態追跡の診断には使えるが、100独立サンプルの精度・信頼区間を主張しない。
- 会議タイプの事前設計目的を渡し、出典の話題名・人間の有効性点数・区間の達成目的ラベルは隠した。ローカル議題が足りない例は不確実とした。
- 原文・順序・重複発話は出典のまま。一部の発話開始時刻は前後する。時刻の隙間や`.`だけの発話から沈黙を断定しない。時間順に並べ替えて同じラベルを流用しない。
- 合成36件はTrainの12元会話だけから作った新規日本語会話。翻訳や実録ではない。生成意図は `generation-intent.jsonl` に分離し、独立評価者に見せていない。
- ラベルはこのアカウントのGPTサブエージェントによる暫定判断。Jev予測から逆算していないが、人手gold・異種モデル合意・客観的真実とは称さない。
- 他者ラベル非閲覧の2回目判定を行った。不一致は初回を暫定保持し、低信頼・不確実を付けた。2人の多数決で正解認定しない。個々の再判定結果と理由を消さず保存した。

## 数字をどう報告するか

現行ラベルでは実録100件のうち**95件がOK**。常にOKと答える多数派ベースラインのラベル一致率は95%。**このデータで80%一致しても、介入精度改善の証拠にはならない。** Validation/Testには脱線ラベルがなく、そのクラスのRecallは測定不能であって0でも100%でもない。合成データを混ぜてこの欠落を隠さない。

実施する評価では、件数付きAccuracy、クラスごとのPrecision/Recall/F1、Macro-F1、混同行列、OK→介入率を出す。未定義指標の扱いを明記する。実録／合成、広い抽出／目的抽出、不確実／比較的確信ありを分け、欠けたクラスを常に表示する。会議系列単位の平均やクラスタ再標本化も検討する。20件のTestの16件正解を「80%」と書くなら16/20も併記する。

本データは正常会話への誤介入や境界事例を調べる診断材料として使える。3クラス80%を説得的に検証するには、独立な日本語実会議と、十分な脱線・停滞の正例、および一部の人手レビューが別途必要。予測結果を見てこのTestを作り直してから同じTest名で性能を報告しない。

スコアは0–1の操作的強さで、確率や人手goldの連続値ではない。寄り道非適用の`tangentIsRelevant`はnullの場合がある。アプリに数値が必要な場合は統合側で非適用フラグを保持して処理する。独立した`gold_status`をスコアの現行閾値で上書きしない。WAIT/SILENCEは画面分類のOKへまとめるが、アプリの内部挙動は本ブランチでは変更していない。

## 再現

Python 3標準ライブラリのみ。モデルAPI・Gateway・追加パッケージは不要。まず固定ソースを取得する（約33MB）。

```bash
curl -fL https://raw.githubusercontent.com/ku-nlp/AMI-ME/c04006257be6ba5cfdb570449a1d064d5e609671/AMI_ME.json -o /tmp/jev-ami-me.json
curl -fL https://groups.inf.ed.ac.uk/ami/AMICorpusAnnotations/ami_public_manual_1.6.2.zip -o /tmp/jev-ami-manual.zip
python3 docs/jev-tuning/scripts/reproduce.py --ami-me /tmp/jev-ami-me.json --manual-zip /tmp/jev-ami-manual.zip
```

入力SHA256を固定値と照合し、一時コピーで抽出→合成の固定レシピ→困難区間への差し替え→ラベル統合→監査を実行、保存済み成果物とのバイト一致を検査する。元ファイルは上書きしない。GPTの同一回答を再生成できるという意味ではなく、**会話・ラベルという版管理した入力からデータ梱包・出典照合を再現する**。

抽出手順は `extract_real.py` と `add_challenge.py`、日本語会話の作成レシピは `author_synthetic.py`。後者は今回GPTが作成した固定台本で、API呼び出しではない。盲検ラベルはサブエージェントが全文を読んで作成し、結果を版管理している。基準・生成手順・入力は保存したが、将来のGPTの出力一致は保証しない。

`audit.py` はsource JSONとの本文・範囲完全一致、AMI原本語彙の時刻範囲内所属（完全な順序アラインメントではない）、各IDとラベルの一対一対応、根拠の発話番号、系列漏洩、Train生成元、重複窓、件数、基準数、データハッシュを検証する。Jevの正解率を検証するテストではない。

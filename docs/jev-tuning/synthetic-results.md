# 日本語合成会議スクリプトによるJev評価

2026-10-18 11:02 JST実測完了。500件を作成・系列分割し、未使用Test100件で選択設定と現行設定はいずれも100/100一致（100%）。今回の合成ベンチマークで80%目標を満たした。ただし現行設定も100%のため、Test上の改善は確認できていない。

## 何を測るか

現在の議題・会議フェーズ・直近6〜12発話から、Jevの3スコアと既存の優先規則で得られる意味3分類が、別担当GPTの参照ラベルと一致するかを測る。既存の画面名称・介入メッセージは変更しない。WAIT/SILENCEに独立した参照ラベルはなく、意味分類では両方をOKへ集約する。

これはAI作成の日本語会議スクリプトに対する、独立したGPT作業のsilverラベルとの一致率。実録会議・人間gold・本番利用者による精度ではない。本文には会議フェーズを明示しており、ASR誤認識やフェーズ欠損への性能は含まない。前回介入から120秒を合成条件として固定し、冷却時間による自動OKで数字を押し上げない。

## 資料・作成・分割

[研究対応表](synthetic-benchmark-v1/research-map.md)、[各32項目の基準](rubric.md)、[独立ラベル用rubric](synthetic-benchmark-v1/annotation-rubric.md)を用いる。28の既存文献・データセット記録、隣接領域のDBDC3実対話125件などは現象理解の背景資料であり、今回の500〜1000本文を原文から抽出したものではない。既存Testの翻訳・人物差し替え・派生例を新Trainへ入れない。

作者の狙いと会話本文を別ファイルに置き、他の担当が議題・phase・会話だけで主ラベルを付ける。不確実例と不一致は除外せず、第三者再確認を保存する。Jevの予測からgoldを作らない。共通の研究参照IDは分類のgoldを裏付ける個別論文証拠ではない。

同一シナリオの問題/正常/回復などの変種はsourceGroupへまとめ、系列ごとにTrain60%・Validation20%・Test20%へ固定する。Train内の5foldも系列単位。語彙重複監査は意味的なテンプレート独立性まで保証しない。作者は複数splitにまたがり、モデル系列も共通する。

## 事前に固定した探索

[事前登録](synthetic-evaluation-plan.md)と固定スナップショットを保存する。モデルは`typesafe-ai/jev-1.14.0`。v2は定義を明示、v3は著作Few-shot例付きの現行アプリ、v4は日本語で末尾・phase・反復/有益な寄り道を明示した定義版。新規Testを読んで候補や例を作らない。

1. Train10件で料金・速度を確認し、成功スコアをキャッシュする。
2. Trainだけを3版で実測。各foldで残り4foldから216通りの閾値を選び、未使用foldを評価する。
3. OOF Macro-F1で上位2版を選び、各版の閾値は全Trainだけで確定する。
4. 上位2設定と従来v3をValidationで比較。Macro-F1、Accuracy、元の閾値への近さで最終設定を固定する。
5. データ・ラベル・質問・Train/Validationスコア・設定のhashを固定してから、baselineと選択設定だけをTestで実測する。

スコアは校正済み確率や客観的な重症度とは主張しない。追加学習ではなく、Promptと閾値の最適化なので学習率・Epochは用いない。CVとグリッド探索は保存済みスコアだけで行い、Gatewayを再呼び出さない。API失敗は同一の固定設定で失敗分だけ再開し、未完了の結果を完成精度として扱わない。

### 限界

このセットで80%は達成したが、実会議での介入精度80%や、チューニングによるTest改善は主張しない。合成特有の反復、議題復帰、担当決定などの表現規則性があり、系列分離だけで作者・文体・意味テンプレートの漏洩は排除できない。研究参照は機構の背景で、具体的なgoldの根拠ではない。

盲検パケットと固定case hashの工程対応は保存される一方、主ラベル自身に判定時inputHashがないため、評価者がそのexact snapshotを読んだ暗号学的証明ではない。新規作者・別モデル/人間の参照判定・ASR誤り・文脈欠損を含む、より難しい外部評価が残る。

# 独立判定・再判定の記録

- `train_labels`: 初回Train 60件。会議目的と発話だけを読み、Jev予測・AMIの有効性点数は見ない。
- `corpus_research`: 初回heldout 40件。同じ非閲覧条件。役割はラベル作成のみで、これを用いたモデルの調整は行っていない。
- root GPT: Trainの12種の元会話だけを見て日本語合成36件を作成。生成意図は別ファイル。heldoutの会話内容を生成に使用しない。
- `rubric`: 初回synthetic 36件とchallenge 10件。生成意図、AMI話題ラベル、他者ラベル、Jev予測を見ずに評価。
- `corpus_research_review`: challenge 10件とsynthetic 36件を再判定。既存ラベル・生成意図は見ない。
- `rubric_boundary_review`: 未再判定の不確実な実会話11件を再判定。既存ラベルは見ない。ただし `ami-TS3008c_008` の短窓については、それ以前の別タスクで同じ議論の長窓を見ていたことを親担当が検出した。未来文脈を利用していないとの自己申告だけでは完全な盲検とは言えないため、その1件の再判定は最終集約に使わず探索的な履歴として残す。
- `train_labels_temporal_review`: 上記短窓1件を追加再判定。元はTrainだけの担当で、そのTest長窓を見ていない。最終集約ではこの記録が短窓の2回目判定として優先される。

初回の意味ラベルはスコア閾値から機械生成していない。数値の閾値規則との不一致は、それだけでラベルを修正する理由にしない。Testを使ったプロンプト／閾値選択はしない。データ構築中には初回ラベルのOK偏重を見て10件を差し替えているため、既存の独立した公開ベンチマークと同等には扱わない。

再判定で不一致が生じた場合は初回ラベルを暫定保持し、不確実フラグと低信頼を付与。異なる理由・代替ラベルを `adjudication.jsonl` に残す。これは専門家の裁定ではない。不一致・不確実な例を高信頼goldと称さない。今後人手で変更する場合は理由と版を残す。

全担当は同じアカウントのGPTであり、異なる基盤モデルの独立性や未学習データであることは保証していない。判定理由と入力単位を保存することで、第三者が再ラベルできる形にした。

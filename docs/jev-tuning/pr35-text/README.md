# PR #35の会話textによるJev精度テスト

PR #35の台本169件に独立ラベルを付け、ラベル固定後に別エージェントが実測した。再チューニングやラベル修正は行っていない。現行v3は159/169（94.08%）、前回選択済みv4は162/169（95.86%）一致した。

## 対象と手順

出典は[PR #35](https://github.com/jphacks/sd_2603/pull/35)、固定コミット`90d82bd6968b4d2163c01a72319003869df2b7b7`。4つのdatasets JSONをバイト列とSHA付きで保存し、[原本ライセンス](SOURCE-LICENSE)も保持した。今回は議題と話者付き会話textのみを入力とし、音声認識、WAV品質、Canvas画像や操作の正しさは評価していない。

1. 新しい`pr35_labeler`へ、匿名ID・agenda・transcriptだけを渡した。原本label、humanAgreement、note、scenario、phase、category、expectedNudgeなどは見せていない。原本のhumanAgreementを人間確認の証拠にしない。
2. 169件の意味3分類・理由・根拠発話・確信度・不確実性・代替ラベルを保存。ID、入力hash、schemaを検証し、[label-freeze.json](label-freeze.json)とコミット`9259e22`で固定した。この時点のJev呼び出しは0。
3. その後に履歴を引き継がない別の`pr35_tester`を起動。固定済みの2設定だけを実測した。最初10件のv3 pilotは全件成功し、その成功スコアを再利用した。
4. 統合担当が全336リクエストの入力隔離・ラベル固定後の時刻・原本hashを検証し、全分類・正解数・混同行列・Macro-F1を別実装で再計算した。[検証記録](verification.json)はすべて成功。

[ラベル](primary-labels.json)は独立したGPT作業のsilverであり、人間goldではない。ラベル担当とテスト担当は別エージェントだが、モデル系列の完全な独立性や人間の妥当性は保証しない。不確実24件も主分母に含め、Jevに合わせたラベル変更・除外はしなかった。

## 不一致とトレードオフ

v4は合計で3件多く一致したが、すべての部分集合で改善したわけではない。hardは4件増え、multiは1件減った。169件は相関する台本群であり、この3件差を統計的に確かな本番改善とは主張しない。

| 指標 | v3 | v4 |

| OKへの誤介入 | 9/124 | 5/124 |
| 脱線の見逃し | 0/27 | 0/27 |

正解数の差は不確実ラベル内で発生している。両設定が共通して不一致だった不確実フラグなしの例は`e1-layout@full`。全不一致のID・固定参照理由・代替ラベル・生スコアは[ERRORS.md](ERRORS.md)に記録した。これを理由にgoldや設定を更新していない。

## 入力・分母の限界

- 同じ議題で会話が完全な前半一致となる長短版・切断版の組が66組あり、独立169会議とは数えない。[重複監査](within-pr-overlap-audit.json)。前回の開発/評価772行との正規化した会話文の完全一致は0だが、意味や文体の独立性まで証明しない。
- 介入から120秒を合成条件として固定。2発話しかない1件は既存runtimeの発話数ゲートでOK/WAITとなり、API呼び出しは不要だった。主分母169に含める。ゲートを除く168件でもv3は158/168（94.05%）、v4は161/168（95.83%）。
- 台本の意味ラベルとの一致であり、実会議・人間の介入判断・音声認識・実時間の介入タイミングの精度ではない。
- 実測用fetch timeoutは15秒で、アプリの5秒とは異なる。観測最大応答は4,641msで5秒超は0だったが、将来の運用レイテンシを保証するものではない。

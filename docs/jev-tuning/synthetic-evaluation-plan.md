# 合成ベンチマーク評価 — 事前登録

2026-10-18。ユーザー承認済みの新しい合成ベンチマーク専用プロトコル。500件を最低目標、1,000件は品質・時刻で判断する。旧実会議Testの85%とは別の実験であり、既存Testを訓練に流用しない。

## 固定した候補

- モデル `typesafe-ai/jev-1.14.0`。
- 質問候補はv2/v3/v4。v2/v3の内容は旧実験から変更なし。v4は独立ルーブリックだけを参照し、合成Test本文・ラベル・作者意図を見ずに作成した日本語定義版。
- 改善前は現行アプリのv3、閾値0.6/0.6/0.6、WAIT0.4。今回は実験上の意味3分類の一致率を主KPIとする。UI名称を変更しない。
- 閾値候補はdrift/stalled/relevance各0.4,0.5,0.6,0.7,0.8,0.9。各Prompt216通り。WAIT0.4は意味分類に影響しないため固定。
- Few-shot例は既存の著作例のみ。新規Testの例や同系列の例をPromptへ入れない。

## データと分割

Proの21c6e7eで本文量産前に系列・split・foldを固定。Train300/Validation100/Test100、100系列で各5例。拡張する場合は新しい系列を追加し、最初の500件の所属を変えない。

取り込み時に合成評価を明示許可する専用APIとmanifest照合を使う。従来の合成Train限定は既定のまま。6〜12発話、phase明示、前回介入から120秒を必須にし、冷却時間や発言不足による自動OKを精度へ混ぜない。phaseをagendaに付加してモデルへ渡し、独立Judgeと同じ文脈を与える。作者意図・ラベル・判定理由はモデルに渡さない。

## 選択手順

1. 10件のTrainで速度・usage・費用見積もり・並列リクエストの動作を確認する。
2. Trainのみをv2/v3/v4で採点し、入力/モデル/質問をキーにキャッシュする。
3. 固定foldの5分割グループCV。各foldで残る4foldのラベルから閾値を選び、未使用foldを評価する。各版のOOF Macro-F1→Accuracy→登録順で上位2版を選ぶ。各版の最終閾値は全Trainだけで選ぶ。
4. 上位2設定と現行v3をValidationで比較し、Macro-F1→Accuracy→元の閾値への近さ→登録順で最終設定を選ぶ。候補リストはValidation採点前にhash固定する。
5. 全500件以上と独立ラベル・監査結果を確認し、設定/データ/質問/Train・Validationスコアのhashを固定。その後にTestをbaselineと採用候補で採点する。
6. Testにエラーがあれば、同じ設定で失敗分だけ再開する。成功スコアは再取得しない。Test後に候補・閾値・ラベルを選び直さない。

主報告はTestの3分類Accuracy（正解数/件数）と80%到達の有無。Macro-F1、クラス別Precision/Recall/F1、混同行列、常に多数派を答えた場合、OKへの誤介入率も併記する。生成系列bootstrapの参考区間を算定する。不確実/判定不一致は主分母から除外しない。信頼例だけの値は補助値として分ける。

## 時間・費用・運用

10:30に件数と品質を確認し、11:00データ固定を優先。最低500件未満の途中成果物を完成ベンチマークとは呼ばない。

専用台帳の上限は4,000試行・保守的予約$4。1要求の予約はUTF-8バイト×3質問×公開入力単価$0.04/M+$0.00064。これは実請求ではない。並列3（最大4）、同一campaignには排他的プロセスロックを掛け、原子的なJSON置換と成功journalで再開する。金額・試行数・usage・失敗は保存する。Pro側の生成/ラベルはGateway0回。

旧実験のTest・台帳・設定選択を上書きしない。実験設定のアプリ採用は、固定表示との整合を別途確認する。合成で80%でも、実録会議・人間gold・日本語本番精度80%とは言わない。

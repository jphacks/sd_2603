# Jev 評価基準 v1 — 事前定義・独立ラベル付け用

作成日: 2026-10-18（日本時間）。本資料はデータ作成・独立判定の仕様であり、アプリ実装や実測結果ではない。Gateway は利用していない。各軸の基準は32項目、計96項目。数を足して点数に変換するチェックリストではなく、会話の証拠を探すための観点である。

## 1. 文献に裏付けられた一般原則と独自仕様

以下の3件を一次資料として確認した（確認日: 2026-10-18）。原文の会話や表は転載せず、一般原則のみ要約する。

- **R1: Clark & Brennan (1991), Grounding in Communication.** [著者所属機関の本文PDF](https://web.stanford.edu/~clark/1990s/Clark%2C%20H.H.%20_%20Brennan%2C%20S.E.%20_Grounding%20in%20communication_%201991.pdf)。本文の Grounding Criterion / Evidence in Grounding / Grounding Changes with Purpose。会話では現在の目的に必要な相互理解を共同で成立させる。確認や修復もその過程を担い、必要な理解の水準は目的や媒体によって変わる。本資料では「確認・言い直し・短い相づちを即停滞とみなさない」根拠として使う。
- **R2: Purver, Körding, Griffiths & Tenenbaum (2006), Unsupervised Topic Modelling for Multi-Party Spoken Discourse.** [論文と書誌](https://aclanthology.org/P06-1003/)、[本文PDF](https://aclanthology.org/P06-1003.pdf)、pp. 17–24。多人数会話の話題分割と話題同定を扱う。本資料では「話題の変化を観察することと、その変化が不適切かを判定することは分ける」ための研究背景として使う。論文が不適切な脱線の検知性能を示したとは解釈しない。
- **R3: Purver, Ehlen & Niekrasz (2006), Shallow Discourse Structure for Action Item Detection.** [著者所属研究機関の論文概要](https://www.sri.com/publication/speech-natural-language-pubs/shallow-discourse-structure-for-action-item-detection/)。発話がアクション項目の割り当て過程で担う役割に基づく階層的な注釈を提案している。本資料では「会議の進捗を発話数だけでなく、提案・議論・合意への寄与から捉える」研究背景として使う。全会議がアクション項目を作るべきだとは主張しない。

**以下の0–1アンカー、32項目ずつの観点、0.6/0.4の閾値、ラベル優先順位、境界幅は、このプロジェクトの独自操作定義である。上記文献がこれらの数値や96項目を検証したという意味ではない。** R1–R3は一般原則の背景であり、項目ごとの実証的妥当性は未検証。尺度の妥当性・Judge間一致・実モデルの精度は今後測定する。

## 2. 判定単位と観察範囲

- 入力は `agenda`（会議目的・現在の議題）、`phase`（発散/比較/決定/報告など、分かる場合）、判定時点までの発話列、発話ID、あれば開始/終了timestamp。将来の発話、後から書かれた要約、最終成果は入力しない。
- 複数議題の会議では、その時点で合意済みの議題変更を反映する。全体会議タイトルだけを現在の議題と取り違えない。
- 評価は提示された範囲の**末尾時点の状態**を対象とする。途中の脱線が解消済みなら、残っている問題がない限り末尾をDRIFTにしない。解消の前後を別例にする場合も同じ元会議グループに置く。
- 関連する直前文脈と末尾の複数発話を読む。一つの単語、言いよどみ、発話長だけでは高得点にしない。持続時間・繰り返し回数の固定ルールは未検証なので設けない。
- 切り出し冒頭の指示語が解決できない、目的が不明、ASRの欠損が核心部分にある場合は、証拠不足を記録する。外部知識で失われた会話を創作しない。
- **timestampや明示的な時間メタデータがなければ沈黙の長さを推論しない。** 改行、三点リーダ、空発話、発話数の少なさは無音時間を証明しない。`[沈黙]`のみでも長さは不明。時間があっても重複発話、編集、文字起こし範囲を確認する。
- 作業のための待機、黙読、投票、思考時間は、その目的と許容範囲が示されれば進行の一部。「長い沈黙=停滞」と機械的には扱わない。
- **有益さは判定時点までの根拠だけで判定する。** 後で採用された、後で失敗したという未来の結果は利用しない。「面白そう」「役立ちそう」だけでは高い有益さの十分な証拠にならない。

## 3. 3軸の操作定義とアンカー

`drifted`: 現在合意された議題・段階から、現在の会話の焦点が離れている程度。有益な寄り道でも焦点が離れていれば高くなり得る。規範的な悪さと同一視しない。

`stalled`: 現在の会議目的に対する前進（理解の更新、候補追加、比較基準の明確化、合意、次の行動など）が止まり、その状態が会話の証拠で維持されている程度。異論、難しい検討、結論がまだないことだけでは高くしない。

`tangentIsRelevant`: 寄り道から現在の議題への**説明可能な接続**と、現在までに得られた判断材料・前提整理・具体化への寄与の程度。寄り道がない場合は `null`（非適用）として記録し、0と混ぜない。アプリが数値を必須とする場合の変換は別途実装側で定義し、非適用フラグを保持する。

| 値 | drifted | stalled | tangentIsRelevant（寄り道がある場合） |
|---|---|---|---|
| 0.0 | 現議題と目的に直接沿う | 目的に沿う新しい進展が明確 | 議題への接続も寄与もない |
| 0.2 | 短い補足・手順確認で焦点は保つ | 一時的な確認や整理で前進を支える | 類似語・連想程度の弱い接続 |
| 0.4 | 別の焦点が現れたが戻る道筋が見える | 重複や未解決が増えたが進展も残る | 接続は説明できるが寄与は曖昧 |
| 0.6 | 主焦点が別話題に移り継続している | 前進が止まったことを複数発話などが裏付ける | 現議題への接続と具体的な寄与が説明できる |
| 0.8 | 議題との接続が乏しい話題が会話を占める | 同じ論点・障害が繰り返され解消策がない | 判断・比較・理解に直接使える材料が得られる |
| 1.0 | 現議題の検討を放棄し別の話題へ完全に移る | 行き詰まりが明示され、再開手段も出ていない | 現議題の重要な制約・決定要因を明確にする |

値は確率ではなく順序的な強さの目安。0.01単位の精密さを主張しない。原則0.1刻みで記録し、閾値境界では可能な範囲を残す。1項目が現れただけで0.6以上にせず、目的・継続・直近の変化・反証を照合する。十分な証拠がなければ不確実とする。

## 5. stalled: 上昇の観点32項目と反例

停滞は進捗の欠如を示す証拠で判定する。単なる対立、否定、無言、同じ単語の使用は十分条件ではない。

| ID | 上げる観察 | 紛らわしい反例・抑制根拠 |
|---|---|---|
| S01 | 同じ主張を根拠追加なしに往復する | 同じ結論を別のデータで検証する |
| S02 | 回答済みの同じ問いを理解の更新なく繰り返す | 聞き取りの修復が一度行われ解消する |
| S03 | 同じ候補A/Bを比較軸なしに行き来する | 新しい比較軸を増やして再評価する |
| S04 | 複数人が「分からない」を繰り返し手段を出さない | 分からない箇所を特定して調査を割り当てる |
| S05 | 問題だけを列挙し、整理も候補追加も止まる | 発散段階で未知のリスクを収集している |
| S06 | 比較基準の必要性を繰り返すが基準を定めない | 基準の異なる解釈を明確にしている |
| S07 | 結論を求め合うが決定者・手続きが決まらない | 投票方法を合意して実施に進む |
| S08 | 担当の押し付け合いが反復し引き受けも代替案もない | 担当の稼働条件を聞き実行可能性を整理する |
| S09 | 同じ情報不足を指摘するだけで取得手段がない | 必要な情報・担当・確認日を決める |
| S10 | 論点が混在したまま同じ誤解が再発する | 論点の分離や定義の確認を進めている |
| S11 | 定義の衝突を指摘されても双方が言い直すだけ | 定義を合わせて次の比較へ進む |
| S12 | 解消済みの懸念を新しい根拠なく何度も再開する | 解消条件を満たしていない事実が出た |
| S13 | 既出案が新規案として繰り返される | 既出案に制約への対処が追加された |
| S14 | 誰も判断材料を増やさず同じ賛否だけが続く | 賛否に理由が付き未整理の価値観が分かる |
| S15 | 同じ批判と防御を反復し検証方法が出ない | 厳しい反論から検証可能な仮説が生まれる |
| S16 | 「どうする」を互いに返すだけで次の一歩が出ない | 問いを分解し最初の小課題を選ぶ |
| S17 | 参加者が行き詰まりを明言し、その後も再開策がない | 行き詰まりの表明後に手順を変えて再開する |
| S18 | 必須の承認がないと分かりながら同じ議論を続ける | 暫定案や承認依頼の準備を作る |
| S19 | 実行不能と確認済みの案へ条件変更なく戻る | 新しい条件により実行可能性が変わった |
| S20 | 結論を先送りする発言だけが反復する | 先送りの理由と再開条件・担当を決める |
| S21 | 説明を重ねても相互理解の証拠が増えず同じ混乱が続く | 相づち・要約・質問で理解が徐々に揃う |
| S22 | 整理案が出ても誰も扱わず同じ論点が循環する | 整理案の欠点を具体的に修正している |
| S23 | 発想会議で同じ案だけが反復し新しい切り口が出ない | 案を増やす段階から整理段階へ合意して移った |

| S31 | 必要な論点を何度も遮り、議論が同じ未解決位置へ戻る | 遮りが事実誤認を正し進行を助ける |
| S32 | 複数の解決案が全て拒否され、拒否条件の説明も代替方針も出ない | 拒否理由から新しい制約が抽出される |

## 6. tangentIsRelevant: 上昇の観点32項目と反例

寄り道があるときだけ適用する。左の効果は発話内の説明や共有資料への言及など、現在までの観察可能な根拠で支持される必要がある。「後から役立つかもしれない」だけで加点しない。有用な話題でも同じ議論を循環すればstalledは独立に上がる。

| ID | 上げる観察 | 紛らわしい反例・抑制根拠 |
|---|---|---|
| T01 | 別案件の実例が現議題と同じ失敗条件を示す | 似た業界というだけで条件が異なる逸話 |
| T02 | 別分野の類推が現在の仕組みの理解を具体化する | 類推を面白がるだけで対応関係がない |
| T03 | 過去事例から現在のリスクに対する対策が示される | 過去の成功を称賛するだけ |
| T04 | 脱線先で現候補の隠れた制約が明らかになる | 現候補と関係のない制約を列挙する |
| T05 | 顧客の別の経験が現在の利用条件を説明する | 顧客の趣味だけを談義する |
| T06 | 関連研究の話が比較すべき評価軸を提供する | 有名な研究名を挙げるだけ |
| T07 | 他製品の例から現在の要件の抜けが具体化する | 他製品への好悪を語るだけ |
| T08 | 用語の由来の補足で現議題の解釈のズレが解消する | 語源談義だけが続き解釈は変わらない |
| T09 | 周辺業務の説明が現案の運用上の依存を示す | 依存のない部署事情の説明 |
| T10 | 別の障害例が今回の原因仮説の反証になる | 同じ単語の障害を関連なく列挙する |
| T11 | 類似案件の見積もりが今の工数比較に使える | 規模や条件を無視した金額の自慢 |
| T12 | 法制度の補足が現案の実行可能性に関わる | 現対象・地域に関係しない制度談義 |
| T13 | 実装の細部が議題の品質条件を満たすかを左右する | 品質条件と無関係な個人の好み |
| T14 | 別チームの経験が現案の引き継ぎ条件を示す | 別チームへの人物評に終わる |
| T15 | 過去の意思決定の背景が現在の禁止条件を説明する | 決定者の思い出話だけ |
| T16 | 一見遠い例が現在のトレードオフの両面を説明する | たとえの雰囲気だけが似ている |
| T17 | 寄り道中に現目的へ使える代替案が具体化する | 目的を置き換えないと使えない案 |
| T18 | 外部の観点が現在の思い込みを具体的根拠で崩す | 根拠なく一般論で否定する |
| T19 | 別の利用者像が対象範囲の境界を明確にする | 対象外利用者の話だけで範囲に戻らない |
| T20 | 他社の失敗から今回確認すべきテストが定まる | 他社の失敗を笑うだけ |
| T21 | 周辺機能の話が今の優先順位の理由を明確にする | 将来機能の願望だけを増やす |
| T22 | 仮定の話から現議題の前提条件を検証する問いが生まれる | 反証不能な空想が続く |
| T23 | 過去の会議の補足が現在の重複作業を防ぐ | 関係のない過去の議論を再演する |
| T24 | 技術史の説明で現在の互換性上の制約が分かる | 年代や人物の知識披露に終わる |
| T25 | 参加者の個人的経験から現在のアクセシビリティ条件が出る | 個人的経験を全利用者に根拠なく一般化する |
| T26 | 他領域の検証方法を現案へ適用できる条件が示される | 適用条件を無視して手法名だけ借りる |
| T27 | 周辺予算の説明が現案に使える資源量を具体化する | 現案に使えない資産の話 |
| T28 | 関連案件のスケジュールが今の依存関係を明らかにする | 関係のない予定の雑談 |
| T29 | 別の失敗経路の説明が現案の監視条件につながる | 漠然と「危険」と言うだけ |
| T30 | 寄り道の説明を受け参加者が現議題の比較を更新する | 「面白い」という反応だけで比較は変わらない |
| T31 | 話者が寄り道と現議題のつながりを説明し、内容もその説明を支持する | 「関係ある」と宣言するだけで接続が示されない |
| T32 | 寄り道で得た具体的条件を使い、本題の問いをより検証可能にする | 本題への復帰を約束するだけで条件は得られない |

## 7. 直接ラベルと現行スコア規則を分ける

### 独立した正解ラベル

ラベラーはJevの予測値、前回精度、期待するクラス、生成時の意図、別Judgeの判定を見ずに会話を読む。初めに下記の質的な定義で `referenceLabel` を選び、発話ID付きの根拠・反証・不確実性を書く。その後で補助的な3軸を記録する。直接ラベルはスコア式から機械生成しない。生成担当の設計ラベルは正解ラベルに転用しない。

- **STALLED**: 現在の進行目的に対し、証拠を伴う停滞が残り、整理・問いの分解・次手の確認が必要と判断される。
- **DRIFT**: 明確な停滞が優先する状況ではなく、現在の焦点が議題から離れ、その寄り道に現在までの十分な有用性が示されず、本題への復帰が必要と判断される。
- **OK**: 本題が進む、必要な確認が進む、有用な寄り道が進む、許可された発散・アイスブレイク・思考・作業が進むなど、上記の介入を裏付ける証拠がない。境界・証拠不足を単にOKへ押し込まず、後述の不確実フラグを付ける。

停滞と無益な脱線が両方明確なら **STALLEDを優先**し、`secondaryLabels: ["DRIFT"]` を残す。有用な寄り道であっても停滞が明確ならSTALLED。正当な議題変更や会議の終了を、放棄・停滞と取り違えない。

### 比較対象としての現行決定規則

```text
if stalled >= 0.6:
    action = INTERVENE
    displayLabel = STALLED
else if drifted >= 0.6 and tangentIsRelevant < 0.6:
    action = INTERVENE
    displayLabel = DRIFT
else if drifted >= 0.4 or stalled >= 0.4:
    action = WAIT
    displayLabel = OK
else:
    action = SILENCE
    displayLabel = OK
```

これらは共有されたベースライン規則であり、最適値でもラベルの客観的真理でもない。`tangentIsRelevant = null` で `drifted >= 0.6` は「寄り道なし」と矛盾するので評価エラーとして再確認し、0扱いでDRIFTにしない。高driftedで有益さ不明の場合も無益と断定せず不確実扱い。WAITとSILENCEはいずれも表示ラベルOKであり、表示3クラスの精度とaction3クラスの精度を混同しない。スコアが欠損している軸の条件は判定不能として記録し、暗黙に0に置換しない。

### 整合例（全て説明用の合成例。実会話・実測ではない）

| 状況 | drifted | stalled | tangentIsRelevant | 現行規則の表示/action |
|---|---:|---:|---:|---|
| 本題の候補比較が進む | 0.1 | 0.1 | null | OK / SILENCE |
| 雑談が会話を占める | 0.8 | 0.2 | 0.1 | DRIFT / INTERVENE |
| 本題で同じ賛否を反復する | 0.1 | 0.8 | null | STALLED / INTERVENE |
| 別分野の例から重要な制約を得る | 0.7 | 0.2 | 0.8 | OK / WAIT |
| 無益な脱線の中で同じ主張を反復する | 0.8 | 0.7 | 0.1 | STALLED / INTERVENE |
| 有益な寄り道だが進展は止まる | 0.7 | 0.8 | 0.8 | STALLED / INTERVENE |

## 8. 不確実性・判定記録・独立性

以下は推奨レコード形式であり、実データのスキーマに合わせて名前を写像してよい。独立性と根拠の意味は維持する。

```json
{
  "exampleId": "example-001",
  "rubricVersion": "1.0",
  "judgeId": "blind-judge-a",
  "judgedAt": "ISO-8601",
  "referenceLabel": "OK",
  "secondaryLabels": [],
  "scores": {"drifted": 0.2, "stalled": 0.1, "tangentIsRelevant": null},
  "scoreRanges": {"drifted": [0.1, 0.3]},
  "tangentApplicable": false,
  "evidence": [{"utteranceIds": ["u4", "u5"], "criterionIds": ["S21"], "reason": "理解の確認が進んでいる"}],
  "counterEvidence": [],
  "confidence": "medium",
  "uncertaintyReasons": [],
  "alternativeLabels": [],
  "labelStatus": "provisional",
  "predictionVisible": false,
  "generationIntentVisible": false
}
```

不確実性の理由コード: `agenda_missing` / `phase_unclear` / `context_truncated` / `asr_unclear` / `timing_missing` / `relevance_unclear` / `boundary_case` / `judge_disagreement` / `multiple_valid_interpretations`。これらの欠損が判定に影響しない場合まで一律に除外せず、影響を理由欄に説明する。

- high: ラベルの根拠と反証を説明でき、欠損を補っても通常はラベルが変わらない。
- medium: 妥当な判定はできるが、文脈・段階・有益さなどに代替解釈がある。
- low: 判定に必要な情報が不足、または複数のラベルが同程度に妥当。`needs_review` とし、決め打ちの正解にしない。
- 独自の境界監査目安として0.6の前後0.1にある軸、またはスコア範囲が閾値を跨ぐ例を再確認候補にする。これは信頼区間ではなく監査ルールである。
- 同じ盲検入力を別Judgeへ渡し、初回結果を見せずに再判定する。不一致は両結果を残し、第三の判定または根拠に基づく再審査を記録する。同一モデルの複数セッションは手順上は独立でも統計的独立や人間との一致を保証しない。
- 再審査では各判定の根拠を見てもよいが、Jevの予測は引き続き見せない。生成時の意図は正解決定後も別ファイルに保持する。
- `timing_missing` のときは沈黙の根拠だけを無効化し、言語的な循環の証拠が十分なら停滞は判定できる。
- Testのラベル再審査は欠損・誤記・基準の一貫性を対象とする。モデルの失敗例を見た後で都合よく正解を変えない。変更した場合は理由、旧値、新値、評価への影響を保存し、元テストの結果も残す。

## 9. データ分離と評価時の利用

- 分割単位は発話・窓でなく、元会議系列。AMIの同一チームの連続会議などを1つの `sourceGroupId` に束ね、Train/Validation/Testを跨がせない。
- 同一会話の隣接窓、翻訳、要約、言い換え、派生合成例も同じグループに置く。内容類似監査だけでは漏洩防止を証明できないため、生成元の系譜を記録する。
- 合成生成に渡せる実会話はTrainのみ。Testを生成プロンプト、Few-shot、閾値最適化、誤り分析によるプロンプト更新に使わない。Validationから生成する場合もTrainには混ぜず、用途を明示する。最も単純な運用はTrain限定とする。
- 閾値やプロンプトを変える際はTrain/Validationを使い、凍結後にTestを評価する。Testを繰り返し見た後の値は探索後の結果として区別する。
- 実会話と合成会話の件数・Accuracy・Macro-F1・混同行列を別々に報告する。Judgeのラベルへの一致率を人間の正解への精度と同一視しない。
- 確定例だけの精度を出す場合も、全件数、不確実件数、除外理由、各クラスの母数を併記し、容易な例だけ選んだ精度に見せない。
- この基準を用意したこと自体は80%達成の証拠ではない。Gateway未実行の段階ではJevの判定精度は未測定とする。

# Jevチューニングの実測結果

2026-10-18 JST。モデル `typesafe-ai/jev-1.14.0`。これはGPTによる暫定参照ラベルとの一致を測る実験であり、人間の正解認定・本番精度ではない。

## 成果と採用内容

| 設定 | Validation n=20 | Test n=20 | Test Macro-F1 | Test OKへの誤介入 |
| --- | ---: | ---: | ---: | ---: |
| v1・従来閾値 | 12/20（60%） | 13/20（65%） | 0.271 | 6/19（31.6%） |
| v2・探索閾値 | 18/20（90%） | 17/20（85%） | 0.315 | 2/19（10.5%） |
| v3・従来閾値：アプリ採用 | 15/20（75%） | 14/20（70%） | 0.283 | 5/19（26.3%） |

探索閾値は drifted **0.6→0.8**、stalled **0.6→0.7**、tangentIsRelevant **0.6維持**。WAIT閾値0.4も固定。648候補（216閾値組×3質問）をValidation Macro-F1で比較し、同点ならAccuracy・従来設定への近さ・質問順で決定した。全候補の値は `evals/tuning/runs/final-001/search.json`。

アプリのモニターは60%/40%を固定表示する。名称・画面表示の変更を避けるため、実運用には閾値を変えない別候補をValidationで選択した。質問v3が選ばれ、Test採点前に `lib/judge/jev-policy.json` へ反映した。Testを見てv2へ切り替えてはいない。質問v3は明示的な基準と著作例を加えたFew-shot版。連続スコアは確率校正済みとは主張しない。

既存 `SILENCE / WAIT / INTERVENE`、介入理由文字列、日本語メッセージ、クールダウン、発言不足ゲートは維持した。新規ラベルにはWAITとSILENCEの独立した区別がないため、上表は「脱線介入／停滞介入／その他」の意味分類であり、既存3アクションの完全一致率ではない。その値は本データでは未測定である。

## 80%目標をどう評価するか

探索候補は17/20=85%だったが、Testの構成はOK19・停滞1・脱線0。常にOKと答えるだけで95%になる。停滞の唯一の正例は、全候補が脱線介入と誤分類した。脱線のRecallは測定不能。実験候補の85%を、実運用や日本語会議の「介入精度80%達成」として使わない。

Macro-F1は3クラス固定、欠落クラスのF1を0とする慣例で算定した。JSONのゼロ除算時Precision/Recallは0で保存するが、support=0のRecallは実質未定義であり「脱線を全件見逃した」を意味しない。各クラスのsupport・予測数と併読する。Testは4会議系列に属する20窓で、独立20会議ではない。Wilson区間はケース独立近似の参考値に限る。

## データと過学習対策

- 英語の設定付きリモコン設計会議100窓。AMI / AMI-ME、CC BY 4.0。90窓の広い抽出と10窓の目的抽出で、代表的無作為標本ではない。
- 会議系列12/4/4で実録Train60 / Validation20 / Test20を固定。Train由来の日本語合成36件はTrainにのみ追加。合成をTestに混ぜない。
- Pro側はJev予測を見ずにラベル作成。再判定・不一致・不確実性は保持した。GPT同士の誤りの相関やフェーズ不足は残る。
- Test入力もラベルもプロンプト生成やFew-shot選択には使用しない。追加著作例は評価窓から採取しない。
- Developmentだけの会議系列holdoutでは、その系列を除いて設定を選び、除外系列を評価。実録と合成の訓練診断を別表示し、一般化性能とは呼ばない。
- 設定・データ・質問・開発スコアのhashを固定してTest採点。中断時は同設定で再開可能。結果を見た再探索は禁止。

元ラベルの不一致例を除外して精度を上げてはいない。今後は独立な日本語実会議の脱線・停滞正例と選択的な人手確認が必要。既存Testを見て調整する場合は開発用へ格下げし、別の未使用Testを用意する。

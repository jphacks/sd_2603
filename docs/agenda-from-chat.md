# チャットからアジェンダを作り、Jev に渡す

`RECALL_CHAT_WEBHOOK_URL` が空の入室は、録画もチャット受信もしない。公開 HTTPS があるときだけ `POST /api/recall/chat` で本文を受け、`lib/agenda` が今日決めることに整える。判定は `/api/recall/video` が、その bot に保存された文字列を Jev に渡す。署名は `RECALL_WEBHOOK_SECRET`（`whsec_`）。整理モデルは `AGENDA_MODEL`、未設定なら `anthropic/claude-haiku-5.5`。

## 届くもの

Recall の `participant_events.chat_message` に含まれるチャット部分は `text` と `to` だけである。ファイル名、MIME、ダウンロード URL、ファイル本体は来ない。

デモで読む入力は次の二つ。

1. 本文に `アジェンダ` を含むチャット
2. `https://docs.google.com/document/d/<id>` で、リンクを知っている全員が開ける Google ドキュメント

取得先は `https://docs.google.com/document/d/<id>/export?format=txt` だけである。Drive のファイル、スプレッドシート、PDF、画像、限定公開のドキュメントは取らない。リダイレクト先が `docs.google.com` または `*.googleusercontent.com` 以外なら捨てる。ログインページのような HTML も捨て、直前のアジェンダを残す。

## 複数のアジェンダ

成功したメッセージは、既存のアジェンダを消さずに 1 件足す。最大 5 件で、6 件目以降は古いものから外す。1 件は目的 1 つと項目 1〜8 個、描画後 900 字以内。全部を空行でつなぎ、2000 字を超えるときは古いブロックから落とす。Jev に渡すのは、その 1 本の日本語である。

```text
目的: 次のリリース方針を決める
1. 提供機能 — 検索か通知かを一つに決める

目的: 公開日と説明者を決める
1. 公開日 — 11月14日か11月28日かに決まっている
```

## 複数ファイルを送ったとき

| 送り方 | 結果 |
| --- | --- |
| 公開ドキュメントの URL を、メッセージを分けて送る | 成功するたびにアジェンダが 1 件足される。失敗したメッセージは足さない |
| 1 つのメッセージに URL を複数書く | 最初の Google ドキュメントだけを取得し、1 件のアジェンダにする。2 つ目以降は読まない |
| 1 つのドキュメントの中に議題が複数ある | 1 件のアジェンダにし、今日決める項目は最大 8 個まで残す |
| Meet 上で PDF、画像、スプレッドシート、Drive ファイルを添付する | 中身は届かない。本文に対象のドキュメント URL も `アジェンダ` も無ければ無視する |

ボット自身の案内文と、目印の無い雑談は整理しない。入力は先頭 8,000 字だけを使う。保存先は、その Node プロセスのメモリで、キーは botId である。開発サーバーではルートごとのモジュール複製で保存先が分かれないよう、`globalThis` 上の Map を共有する。Vercel の複数インスタンスではこのメモリは共有されない。

## 自動音声判定への反映

音声ワーカーは判定のたびに、操作トークンで認証した動画 API の `mode: "agenda"` から、その bot の最新アジェンダと `agendaVersion` を取得する。議案書とチャットの整理結果も自動判定に反映する。成功した資料は従来どおり最大5件のアジェンダへ追加し、「現在の議題を1件選ぶ」機能ではない。

資料の取得・整理中は旧アジェンダで介入しない。更新開始時点で世代を無効化し、失敗した場合は本文を維持したまま旧推薦を破棄する。取得失敗時にワーカーが古い議題へフォールバックすることはない。世代が変わると保留中の脱線推薦を消し、新世代でも新しい final を伴う2回の推薦が必要になる。処理した文字起こしは履歴へ残す。

`evaluate` と `display` はアジェンダ本文・世代を照合する。モデル応答待ち、描画待ち、発言再開チェック待ちに更新された推薦は409で取り消し、失効したモデル結果は監視画面の最新判定に保存しない。実出力成功だけが介入・クールダウンとして記録される。静音待ち・8秒で待機画像へ戻す仕組みは従来どおり。

アジェンダ保存は単一アプリプロセスのメモリであり、再起動時の復元や複数インスタンス間の共有は未実装。Recallへの送信開始後に発生した更新までは原子的に取り消せない。確認は送信直前までであり、完全な排他保証ではない。

## 検証

2026-10-17。単体テストは `lib/agenda/agenda.test.mjs`。

- 公開 Google ドキュメント以外の URL を拒否する。Drive、スプレッドシート、別ホスト、認証情報付き URL を含む。
- 1 メッセージ内の複数 URL は、最初のドキュメントだけを選ぶ。
- 目印の無いチャット、ボットの案内、署名の無い webhook はアジェンダを変えない。
- 後から来たアジェンダは、前のものと並べて保持する。
- ドキュメント取得の失敗と、Google 以外へのリダイレクトは、直前のアジェンダを残す。
- 長い項目は後ろから落とし、判定に渡す文字列は 2000 字以内に収める。

同じ日の Meet で、公開トンネル経由の webhook を付けたボットに対して確認した。

- webhook URL がプレースホルダのままだと、入室 API は Recall から 400 になる。実在する `https://` にすると入室できる。
- `アジェンダ` を含むチャットは `POST /api/recall/chat` が 200 になり、処理時間は約 4 秒だった。
- 発話を 1 件だけにした判定では Jev を呼ばず、カメラは `unchanged` のまま、保存済みの整理結果を返せた。内容は Hack Day の開発テーマ、方針、当日までの準備を決める 1 件だった。
- その後の 1 通は webhook が 200 になったが、判定側から見える文は更新されなかった。受信と判定でメモリが分かれていたため、保存 Map を `globalThis` で共有する修正を入れた。修正後に、2 通を足した状態の再確認はまだしていない。
- Meet のファイル添付について、届いた `text` を控えるスパイクはしていない。Recall のペイロードにファイル項目が無いことと、対象外 URL を拒否するテストで、添付そのものは取り込まないと判断した。
